# defer в Go — расширенное руководство

**Главное:** `defer` откладывает вызов функции до **выхода из текущей функции**. Работает даже при `panic`. Порядок выполнения — **LIFO** (последний объявленный — первый выполненный). Аргументы вычисляются **в момент объявления** `defer`, а не при выполнении.

## Основы

### Как работает

`defer` добавляет вызов в **стек**. Все отложенные вызовы выполняются **перед возвратом** из функции, в **обратном порядке** объявления.

```go
func main() {
    defer fmt.Println("Первый defer")
    defer fmt.Println("Второй defer")
    fmt.Println("Основная работа")
}

// Вывод:
// Основная работа
// Второй defer
// Первый defer
```

### Классический пример — закрытие файла

```go
func readFile(filename string) error {
    file, err := os.Open(filename)
    if err != nil {
        return err
    }
    defer file.Close()   // закроется ВСЕГДА: при return, ошибке, panic

    // работа с файлом...
    return nil
}
```

## Порядок выполнения (LIFO)

```go
func countdown() {
    for i := 1; i <= 3; i++ {
        defer fmt.Println(i)
    }
    fmt.Println("Старт!")
}

// Вывод:
// Старт!
// 3
// 2
// 1
```

**Правило:** последний `defer` — выполняется **первым**.

## Когда вычисляются аргументы

⚠️ **Аргументы вычисляются в момент объявления `defer`**, а не при выполнении.

```go
func main() {
    x := 0
    defer fmt.Println("defer 1:", x)   // x = 0 (зафиксировано)
    x++
    defer fmt.Println("defer 2:", x)   // x = 1 (зафиксировано)
    x++

    fmt.Println("main:", x)   // x = 2
}

// Вывод:
// main: 2
// defer 2: 1
// defer 1: 0
```

### Хочешь видеть актуальное значение — используй анонимную функцию

```go
func main() {
    x := 0
    defer func() {
        fmt.Println("defer 1:", x)   // берётся в момент ВЫПОЛНЕНИЯ
    }()
    x++
    defer func() {
        fmt.Println("defer 2:", x)
    }()
    x++

    fmt.Println("main:", x)
}

// Вывод:
// main: 2
// defer 2: 2
// defer 1: 2
```

**Почему так:** анонимная функция захватывает **адрес переменной** `x`, а не её значение. К моменту вызова `defer` — `x` уже равен `2`.

| Форма | Что фиксируется |
|---|---|
| `defer fmt.Println(x)` | **Значение** `x` в момент объявления |
| `defer func() { fmt.Println(x) }()` | **Адрес** `x`, читается при выполнении |

## defer и именованные возвращаемые значения

`defer` **может изменить** именованный результат.

```go
func double(x int) (result int) {
    defer func() {
        result *= 2   // изменит возвращаемое значение
    }()
    return x
}

fmt.Println(double(5))   // 10
```

**Без именованного результата** — `defer` не влияет:

```go
func double(x int) int {
    result := x
    defer func() {
        result *= 2   // изменит только локальную переменную
    }()
    return result
}

fmt.Println(double(5))   // 5
```

⚠️ **Совет из курса:** не менять возвращаемое значение в `defer` без реальной необходимости. Это неочевидно для читателя.

## defer и panic (recover)

`defer` + `recover` — стандартный способ **перехватить панику** и превратить её в ошибку.

```go
func safeDivide(a, b int) (_ int, err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("произошла паника: %v", r)
        }
    }()

    return a / b, nil
}

res, err := safeDivide(4, 0)
// err: "произошла паника: runtime error: integer divide by zero"
```

**Ключевое:**
- `recover()` работает **только внутри `defer`**.
- Используем **именованный** `err`, чтобы записать в него ошибку.
- `_ int` — результат игнорируем.

## ⚠️ defer в цикле

**Проблема:** `defer` в цикле **накапливается**. Выполнится **только при выходе из функции**, а не на каждой итерации.

```go
func processFiles(filenames []string) {
    for _, name := range filenames {
        f, err := os.Open(name)
        if err != nil {
            continue
        }
        defer f.Close()   // ❗ все файлы откроются и останутся открытыми до конца функции
        // обработка...
    }
}
```

**Что плохо:**
- 1000 файлов → 1000 открытых дескрипторов одновременно.
- Может закончиться лимит (`too many open files`).

**Решение:** вынести обработку в **отдельную функцию**.

```go
func processFile(filename string) error {
    f, err := os.Open(filename)
    if err != nil {
        return err
    }
    defer f.Close()   // ← теперь закрывается на выходе из processFile

    // обработка...
    return nil
}

func processFiles(filenames []string) {
    for _, name := range filenames {
        if err := processFile(name); err != nil {
            fmt.Println("Ошибка:", err)
        }
    }
}
```

**Правило:** **не создавай `defer` в цикле.** Если очень нужно — оберни тело цикла в функцию.

## Практические применения

### 1. Освобождение ресурсов

```go
file, _ := os.Open("data.txt")
defer file.Close()

conn, _ := db.Connect()
defer conn.Close()

mu.Lock()
defer mu.Unlock()
```

**Правило:** открыл — сразу `defer Close()`. Не в конце функции, а **сразу после открытия**.

### 2. Логирование времени выполнения

```go
func longRunning() {
    defer func(start time.Time) {
        fmt.Printf("Выполнялось: %v\n", time.Since(start))
    }(time.Now())

    time.Sleep(2 * time.Second)
}
```

⚠️ Обрати внимание: `time.Now()` — **аргумент**, вычисляется в момент объявления `defer`. Внутри — уже захваченное значение.

### 3. Обработка паники

```go
defer func() {
    if r := recover(); r != nil {
        log.Printf("Паника: %v", r)
    }
}()
```

## Лучшие практики

| № | Правило |
|---|---|
| 1 | Закрывай ресурсы через `defer` **сразу после открытия** |
| 2 | `recover()` — только в `defer`, только для **критических** мест |
| 3 | Помни про **LIFO** — важен порядок |
| 4 | Аргументы вычисляются **при объявлении** — если нужны актуальные, анонимка |
| 5 | **Не создавай `defer` в цикле** — выноси в отдельную функцию |
| 6 | Не меняй именованное возвращаемое значение в `defer` без необходимости |
| 7 | Не пихай **сложную логику** в `defer` — читаемость падает |

## Подводные камни

### 1. Аргументы «замораживаются» при объявлении

```go
x := 0
defer fmt.Println(x)   // напечатает 0, даже если x изменится
x = 42
```

**Решение:** используй анонимную функцию, если нужны актуальные значения.

### 2. `defer` в цикле копит открытые ресурсы

См. раздел «defer в цикле» — выноси в отдельную функцию.

### 3. `recover()` вне `defer` — всегда `nil`

```go
if r := recover(); r != nil { ... }   // ❌ не работает
```

### 4. `defer` с `nil`-интерфейсом

Если `err` — `nil`-указатель внутри интерфейса, проверка `if err != nil` может врать. Помни про **пару (тип, значение)**.

### 5. `defer` и `os.Exit`

```go
func main() {
    defer fmt.Println("defer выполнится")
    os.Exit(0)   // ← defer НЕ выполнится
}
```

`os.Exit` **не вызывает** `defer`. Никакие отложенные вызовы не сработают.

## Запомнить

- `defer` откладывает вызов до **выхода из функции**.
- Порядок выполнения — **LIFO** (последний объявленный — первый).
- Аргументы вычисляются **в момент объявления** `defer`.
- **Анонимная функция** в `defer` читает переменные **в момент выполнения**.
- `defer` работает даже при **`panic`** — это его ключевая фича.
- `recover()` — **только внутри `defer`**.
- `defer` может менять **именованное** возвращаемое значение.
- **Не создавай `defer` в цикле** — выноси обработку в отдельную функцию.
- `os.Exit` — **не выполняет** `defer`.
- Открыл ресурс — **сразу `defer Close()`**, а не в конце.
