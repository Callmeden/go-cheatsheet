# Отладка Go приложений (Debug)

**Главное:** отладчик позволяет **остановить** программу, посмотреть значения переменных, пройти код по шагам и понять, что пошло не так. Альтернатива `fmt.Println` — но в разы мощнее.

**Основной инструмент:** **Delve** (`dlv`) — стандартный отладчик Go. Работает под капотом VS Code, но умеет и в терминале.

---

## Установка

1. **VS Code + расширение Go** (от Google) — даёт подсветку, автодополнение, отладку.
2. **Delve:**
   ```bash
   go install github.com/go-delve/delve/cmd/dlv@latest
   ```
3. **Проверь `PATH`:** `$GOPATH/bin` должен быть в `PATH`, иначе VS Code не найдёт `dlv`.

---

## Настройка `launch.json`

1. `Ctrl+Shift+P` → **`Debug: Add Configuration`** → **Go** → **`Go: Launch Package`**.
2. Создаётся `.vscode/launch.json`.

**Пример конфигурации (с аргументами и env):**
```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Debug with Args",
            "type": "go",
            "request": "launch",
            "mode": "auto",
            "program": "${workspaceFolder}/cmd",
            "args": ["5", "+", "3"],
            "env": { "DEBUG_MODE": "true" }
        }
    ]
}
```

- `program` — путь к папке с `main.go`.
- `args` — аргументы командной строки (то, что попадает в `os.Args`).
- `env` — переменные окружения.

## Три режима отладки (Delve)

| Режим | Когда использовать | Команда под капотом |
|---|---|---|
| **launch** | Отладка локального кода с самого начала | `dlv debug` |
| **attach** | Подключиться к **уже запущенному** процессу | `dlv attach <pid>` |
| **connect / remote** | Удалённая отладка (сервер, Docker, k8s) | `dlv debug --headless ...` |

### `launch` — запуск своего пакета

```json
{
  "name": "Debug Launch",
  "type": "go",
  "request": "launch",
  "mode": "auto",
  "program": "${workspaceFolder}",
  "args": ["5", "+", "3"]
}
```
Delve компилирует с отладочной информацией и запускает.

### `attach` — подключение к живому процессу

```json
{
  "name": "Attach to Process",
  "type": "go",
  "request": "attach",
  "processId": 12345
}
```
Работает через `ptrace` (Linux/macOS). ⚠️ Процесс должен быть собран с `-gcflags=all="-N -l"` — чтобы отключить оптимизации и сохранить символы.

### `connect` — удалённая отладка

На сервере (в контейнере):
```bash
dlv debug --headless --listen=:2345 --api-version=2 --accept-multiclient
```

В `launch.json`:
```json
{
  "name": "Connect to Server",
  "type": "go",
  "request": "launch",
  "mode": "remote",
  "remotePath": "/app",
  "port": 2345,
  "host": "127.0.0.1",
  "program": "${workspaceFolder}"
}
```

⚠️ **Нужно:** пробросить порт `2345` из контейнера/сервера. Если пути на локальной машине и сервере отличаются — используй `remotePath`.

**Применение:** отладка в Docker, Kubernetes, удалённом сервере. В проде — с осторожностью.

## Что можно делать в отладчике VS Code

### Точки останова (breakpoints)
- Клик слева от номера строки → красная точка.
- Программа остановится здесь при выполнении.

### Запуск
- **F5** или зелёная кнопка → выбор конфигурации → программа стартует и останавливается на первой точке.

### Панель Variables
- Все локальные переменные, аргументы, состояние стека, глобальные.
- **Лучше, чем `fmt.Println`:** не нужно заранее писать лог — видно всё в реальном времени.

### Пошаговое выполнение

| Клавиша | Действие |
|---|---|
| **F10** | Step Over — выполнить строку, перейти к следующей (без захода в функции) |
| **F11** | Step Into — зайти внутрь вызываемой функции |
| **Shift+F11** | Step Out — выйти из текущей функции |

### Изменение переменных на лету
- Двойной клик по значению в панели Variables → ввести новое.
- Позволяет тестировать альтернативные сценарии **без перезапуска**.

### Работа с ошибками
- Передай заведомо «плохие» аргументы (например, деление на ноль) — и посмотри пошагово, как программа доходит до ошибки.

---

## Когда использовать отладчик

- Код сложный, много ветвлений.
- Подозрение на некорректное состояние переменных.
- Гонки данных (поведение зависит от порядка вызовов).
- `fmt.Println` уже не отвечает на вопрос «почему всё сломалось?».

**Delve — полноценный инструмент.** Можно использовать не только в VS Code, но и в **терминале** (команды `dlv debug`, `dlv attach`, `dlv test`).

## Запомнить

- **Delve (`dlv`)** — стандартный отладчик Go, работает под VS Code.
- Ставится через `go install github.com/go-delve/delve/cmd/dlv@latest`.
- Конфиг — `.vscode/launch.json`.
- **Три режима:** `launch` (свой код), `attach` (живой процесс), `connect/remote` (сервер, Docker).
- Клавиши: **F5** (запуск), **F10** (Step Over), **F11** (Step Into), **Shift+F11** (Step Out).
- Можно **менять переменные** во время паузы — без перезапуска.
- Когда `fmt.Println` не помогает — иди в отладчик.
