# Указатели (Pointers)

**Главное:** указатель — переменная, которая хранит **адрес** другой переменной, а не её значение.

**Зачем нужны:**
- Менять оригинал через функцию (передача «по ссылке»).
- Не копировать большие данные (структуры, массивы).
- Управлять состоянием объекта из разных мест программы.

---

## Синтаксис

| Запись | Что делает |
|---|---|
| `*T` | тип «указатель на T» |
| `&x` | получить адрес переменной `x` |
| `*p` | разыменовать: получить/изменить значение по адресу |

**Пример:**
```go
v := 42
p := &v            // p — *int, адрес v
fmt.Println(*p)    // 42 (значение по адресу)
*p = 21            // изменили v через указатель
fmt.Println(v)     // 21
```

**Объявление без инициализации:**
```go
var p *int         // nil-указатель
```

---

## Передача в функцию

```go
func increment(num *int) {
    *num = *num + 1    // меняем значение по адресу
}

a := 10
increment(&a)
fmt.Println(a)         // 11
```

**Swap через указатели:**
```go
func swap(x, y *int) {
    *x, *y = *y, *x
}
```

---

## Указатели на массивы и структуры

**Массив:**
```go
func modifyArray(arr *[3]int) {
    (*arr)[0] = 100
}
nums := [3]int{1, 2, 3}
modifyArray(&nums)     // nums = [100 2 3]
```

**Структура** (упрощённый доступ — без `(*p)`):
```go
type Point struct{ X, Y int }

func updatePoint(p *Point) {
    p.X = 10           // то же, что (*p).X = 10
    p.Y = 20
}
```

---

## nil-указатели

```go
var p *int
// fmt.Println(*p)    // 💥 panic: invalid memory address
```

**Перед разыменованием — проверяй на nil:**
```go
if p != nil {
    fmt.Println(*p)
}
```

---

## Функция `new`

Создаёт **безымянный** объект типа `T` и возвращает указатель на него. Объект инициализируется zero value.

```go
p := new(int)     // *int, значение 0
*p = 8            // *p == 8
```

**`new` vs `make`:**

| | Что делает |
|---|---|
| `new(T)` | создаёт объект типа T, возвращает `*T` |
| `make(T)` | только для слайсов, мап, каналов; возвращает инициализированное значение |

```go
p := new(int)        // *int → 0
s := make([]int, 5)  // []int длины 5
```

🆕 **По материалу курса:** в Go 1.26 добавили перегрузку `new(expr)` — инициализация значением:
 ```go
 p := new(int(42))   // *int со значением 42
 ```

**Память:** области, выделенные через `new` и `make`, очищаются GC автоматически, когда на них не остаётся ссылок.

---

## Когда использовать указатели

**✅ Передавать по указателю:**
- **Большие структуры** (условно > 64 байт) — экономия на копировании.
- **Объекты, состояние которых надо менять** внутри функции.
- **Примитивы — только если нужно изменить их значение** через функцию.

**❌ НЕ передавать по указателю:**
- **Примитивные типы** (`int`, `float64`, `string`, `bool`) — копия дешевле указателя.
- **Маленькие структуры** — копия дешевле.
- **Ссылочные типы** — уже передаются «по ссылке»:
  - слайсы `[]T`
  - карты `map[K]V`
  - каналы `chan T`
  - функции
  - интерфейсы

**Почему ссылочные типы не нужно оборачивать в указатель:**
- Передача по значению уже работает как ссылка.
- Дополнительный `*` только усложняет код.
- Производительность не выигрывает.

---

## Подводные камни

### 1. Разыменование nil-указателя
```go
var p *int
*p = 1    // 💥 panic
```
Всегда проверяй `if p != nil` перед разыменованием.

### 2. Указатель на указатель
`**T` — существует, но в 99% случаев это признак плохого дизайна. Если хочется `**T` — скорее всего, стоит вернуть новое значение из функции, а не менять через двойной указатель.

### 3. Указатель не продлевает жизнь объекту «навсегда»
GC соберёт объект, когда на него **не останется ссылок**. Пока указатель жив — объект жив.

### 4. `new` и структуры — читаемость
`new(Point)` редко используется. Обычно пишут `&Point{}` — то же самое, но нагляднее:
```go
p1 := new(Point)    // *Point, поля = 0
p2 := &Point{}      // *Point, поля = 0
```

---

## Запомнить

- Указатель хранит **адрес**, а не значение.
- `&` — взять адрес, `*` — разыменовать.
- nil-указатель: читать нельзя → паника. Проверяй `if p != nil`.
- `new(T)` → `*T` с zero value. `make(T)` → для slice/map/chan.
- Большие структуры и «меняемые» объекты — по указателю.
- Примитивы и **ссылочные типы** (slice, map, chan, func, interface) — по значению.
- `p.X` — это `(*p).X`, Go разыменовывает автоматически.

# Структуры (Structs)


**Главное:** структура — пользовательский тип, который объединяет несколько полей разных типов под одним именем. Контейнер для логически связанных данных.

**Зачем:**
- Группировка данных об одном объекте.
- Модели данных: `User`, `Point`, `Rectangle`.
- Удобная передача связанных данных между функциями.

---

## Синтаксис объявления

```go
type User struct {
    Name  string
    Age   int
    Email string
}
```

**Экспорт (видимость за пределами пакета):**
- Имя с **заглавной** буквы → публичное (экспортируемое).
- Имя с **маленькой** → приватное (только внутри пакета).
- Это касается и структуры целиком, и её отдельных полей.
- Позволяет: дать доступ к структуре, но скрыть отдельные поля.

---

## Инициализация

### 1. Zero value (без значений)

Все поля получают zero value своего типа:
- числа → `0`, строки → `""`, bool → `false`, slice/map/chan/func → `nil`.

```go
var user User
fmt.Println(user)   // {"" 0 ""}  — три поля, все пустые

user.Name = "Bob"
user.Age = 40
user.Email = "bob@example.com"
fmt.Println(user)   // {Bob 40 bob@example.com}
```

### 2. С именованными полями (рекомендуемый способ)

```go
u := User{
    Name:  "Alice",
    Age:   30,
    Email: "alice@example.com",
}
```
**Плюсы:** читаемо, не ломается при изменении порядка полей в структуре.

### 3. Без имён полей (позиционно) — ❌ НЕ рекомендуется

```go
u := User{"Bob", 40, "bob@example.com"}
```
**Проблемы:**
- Непонятно, какое значение какому полю.
- Ломается тихо, если поменять порядок полей в объявлении.

**В проектах не использовать.**

### 4. Указатель на структуру

```go
// Вариант A — литерал + адрес (рекомендуется)
u1 := &User{Name: "Charlie", Age: 28}
fmt.Println(u1.Name)   // Charlie

// Вариант B — new + заполнение
u2 := new(User)
u2.Name = "Bob"
u2.Age = 40
```

Go **автоматически разыменовывает** указатель при доступе к полям: пишем `u.Name`, а не `(*u).Name`.

**Когда брать указатель:**
- Большая структура (экономия на копировании).
- Нужно менять поля внутри функции.

**Рекомендация:** `&User{}` удобнее, чем `new(User)`.

### 5. Вложенные структуры

```go
type Address struct {
    City  string
    State string
}

type Person struct {
    Name    string
    Address Address
}

p := Person{
    Name: "John",
    Address: Address{
        City:  "New York",
        State: "NY",
    },
}
fmt.Println(p.Address.City)   // New York
```

### 6. Анонимные структуры

Используются **один раз**, без объявления именованного типа.

```go
person := struct {
    Name string
    Age  int
}{
    Name: "Tom",
    Age:  32,
}
fmt.Println(person.Name, person.Age)
```

**Когда:** временные данные, тесты, прототипы.
**Плюс:** без объявления типа, компактно.
**Минус:** нельзя переиспользовать.

---

## Выравнивание структур (memory alignment)

Реальный размер структуры в памяти может быть **больше** суммы размеров её полей — из-за выравнивания (padding).

На практике нужно редко: только при низкоуровневых оптимизациях.
---

## Запомнить

- Структура — именованный набор полей разных типов.
- Заглавная буква = экспорт, маленькая = приватность внутри пакета.
- Zero value даёт безопасное значение по умолчанию.
- Инициализация: `User{}`, `User{Name: "..."}`, `&User{}`. **Позиционную — не использовать.**
- `&User{}` — идиоматично. `new(User)` — рабочий вариант, но реже.
- Go сам разыменовывает указатель: `u.Name`, а не `(*u).Name`.
- Вложенные структуры — для моделирования «объект в объекте».
- Анонимные структуры — для одноразовых данных.
- Реальный размер структуры в памяти может отличаться от суммы полей (padding).


# Методы (Methods)

**Главное:** метод — это функция с **получателем (receiver)**, привязанная к определённому типу (обычно структуре). Добавляет поведение к типу.

**Синтаксис:**
```go
func (receiver Type) MethodName(params...) returnType {
    // тело
}
```

**Пример:**
```go
type Rectangle struct {
    Width, Height int
}

func (r Rectangle) Area() int {
    return r.Width * r.Height
}

rect := Rectangle{Width: 5, Height: 10}
fmt.Println(rect.Area())   // 50
```

Метод вызывается через экземпляр: `rect.Area()`.

---

## Типы получателей

### Value receiver (по значению)
```go
func (r Rectangle) Perimeter() int {
    return 2 * (r.Width + r.Height)
}
```
- Работает с **копией** структуры.
- Оригинал **не меняется**.
- Когда: метод только читает данные.

### Pointer receiver (по указателю)
```go
func (r *Rectangle) Scale(factor int) {
    r.Width *= factor
    r.Height *= factor
}
```
- Работает с **оригиналом**.
- Может **менять поля** структуры.
- Когда: метод изменяет структуру или она большая.

**Наглядная разница:**
```go
type Counter struct{ Value int }

func (c Counter) Increment()  { c.Value++ }   // копия — оригинал не изменится
func (c *Counter) Decrement() { c.Value-- }   // оригинал — изменится

counter := Counter{Value: 10}
counter.Increment()
fmt.Println(counter.Value)   // 10
counter.Decrement()
fmt.Println(counter.Value)   // 9
```

---

## Как выбирать receiver

**Практическое правило:**
- **Только читает** → value receiver.
- **Меняет поля** или структура **большая** → pointer receiver.

**Совет из практики:**
> Если есть сомнения — для **всех методов структуры** выбирай **pointer receiver**.
> Причина: value receiver копирует всю структуру (дорого для больших данных), а для изменений нужен указатель.
> Поэтому в реальных Go-проектах ты часто увидишь `(u *User)`, `(s *Server)` и т.д.

⚠️ **Одно правило из «Effective Go»:** не смешивай типы receiver'ов в одном типе. Если хоть один метод требует `*T` — делай все методы с `*T`. Иначе путаница.

---

## Методы для пользовательских типов

Можно определять методы для **своего типа**, основанного на встроенном:

```go
type MyInt int

func (m MyInt) IsEven() bool {
    return m%2 == 0
}

num := MyInt(4)
fmt.Println(num.IsEven())   // true
```

**Нельзя:**
- Определять методы для **чужих типов** (`int`, `string` из стандартной библиотеки).
- Определять методы для **типов из других пакетов** — даже если это твой пакет, но другой.

Правило простое: **метод можно определить только для типа, объявленного в твоём пакете.**

---

## Перегрузка методов

В Go **нет перегрузки**. Нельзя объявить два метода с одинаковым именем, но разными параметрами.

```go
func (u User) Greet() string { ... }
// func (u User) Greet(name string) string { ... }   // ❌ ошибка компиляции
```

Это соответствует философии Go: простота, читаемость, предсказуемость.

---

## Запомнить

- Метод = функция + **receiver** (получатель).
- Value receiver → копия, не меняет оригинал.
- Pointer receiver → оригинал, может менять поля.
- **Правило:** читает → value; меняет или большая структура → pointer.
- **Практика:** если сомневаешься — для всех методов структуры ставь pointer receiver.
- **Не смешивай** value/pointer receiver в одном типе.
- Методы можно определять только для типов **своего пакета**.
- Перегрузки методов в Go **нет**.

# Публичные и приватные поля и методы (Export)

**Главное:** в Go **нет** модификаторов `public` / `private` / `protected`. Правило одно: **заглавная буква = экспорт, строчная = приватность внутри пакета**.

**Правило работает для всего:**
- структур
- полей структур
- методов
- функций
- интерфейсов
- переменных
- констант

---

## Пример со структурой

```go
type User struct {
    Name  string   // экспортируется — видно из других пакетов
    email string   // приватное — только внутри пакета
}
```

- Из другого пакета: `user.User{Name: "Alice"}` — ✅
- Прочитать/присвоить `email` из другого пакета — ❌ компилятор не даст.

**Пример с методами:**
```go
func (u *User) SayHello() string {   // экспортируется
    return "Hello, " + u.Name
}

func (u *User) secret() string {     // приватный
    return u.email
}
```

---

## Зачем нужна приватность

### 1. Инкапсуляция
Скрыть внутреннее устройство. Дать доступ только через определённые методы — там можно валидировать, обновлять связанные поля, держать инварианты.

### 2. Устойчивость API
- **Экспортированное** = часть API = обещание «это будет работать и дальше».
- **Неэкспортированное** = можно менять/удалять/переименовывать без страха сломать чужой код.

---

## Приём: приватная структура + публичный конструктор

```go
type config struct {
    port int
}

func NewConfig(port int) *config {
    return &config{port: port}
}
```

**Зачем:**
- Запрещает снаружи создавать `config{port: -1}` напрямую.
- Всё создание идёт через `NewConfig` — там можно проверить/провалидировать.
- Это **идиоматичный паттерн Go**: `NewXxx(...)` для создания сложных объектов.

> 💡 Запомни: **`NewXxx`** — соглашение об именовании конструкторов в Go. Если функция возвращает указатель на структуру и создаёт её — называй `NewXxx`.

---

## Приватность работает на уровне ПАКЕТА, не файла

- Несколько `.go` файлов в **одном пакете** → видят друг друга полностью (включая приватные поля).
- **Другой пакет**, даже в том же модуле, **не видит** неэкспортируемые имена.

```
myproject/
├── main.go         (package main)
├── user/
│   ├── user.go     (package user)
│   └── helpers.go  (package user)   ← видит приватное из user.go
└── server/
    └── server.go   (package server) ← НЕ видит приватное из user
```

---

## Запомнить

- **Заглавная** = экспорт, **строчная** = приватность в пакете.
- Работает одинаково для всех сущностей: поля, методы, типы, функции, константы.
- Приватность — **на уровне пакета**, не файла.
- Экспорт = контракт = нельзя менять без ломки чужого кода.
- Идиома: **приватная структура + `NewXxx` конструктор** — для контроля создания.
- В Go нет ключевых слов `public`/`private` — только регистр первой буквы.

# Подводные камни указателей

## 1. `range` и адрес переменной итерации

**Проблема:** хочешь сохранить указатели на элементы слайса через `range`:

```go
users := []User{
    {Name: "Alice"},
    {Name: "Bob"},
    {Name: "Charlie"},
}

m := make(map[string]*User)
for _, u := range users {
    m[u.Name] = &u   // ⚠️ берём адрес переменной итерации
}
```

**Поведение до Go 1.22:**
```
Alice   -> Charlie
Bob     -> Charlie
Charlie -> Charlie
```
**Почему:** переменная `u` создавалась **один раз**, на каждой итерации в неё просто копировалось новое значение. Адрес `&u` — один и тот же. К концу цикла в `u` лежит последний элемент → все указатели смотрят на него.

**Поведение с Go 1.22+:** переменная `u` создаётся **на каждой итерации** → каждый `&u` уникален → всё работает как ожидается.

### Как писать безопасно во всех версиях

Бери адрес **по индексу**:

```go
for i := range users {
    m[users[i].Name] = &users[i]
}
```

`&users[i]` — это настоящий адрес конкретного элемента массива, не зависит от версии.

> ⚠️ **Запомни идиому:** `&users[i]` вместо `&u` в цикле `range`, если нужен стабильный указатель на элемент.

---

## 2. Нельзя брать адрес значения из map

```go
m := map[string]int{"apple": 3}
ptr := &m["apple"]   // ❌ ошибка компиляции
// cannot take the address of m["apple"]
```

**Почему:** значения в map **не имеют стабильного адреса**. Go может их перемещать при росте/перестройке хэш-таблицы. Разрешить `&m[key]` — значило бы дать «висячий» указатель.

### Как работать со значениями map по ссылке

| Способ | Работает | Когда |
|---|---|---|
| `&m["key"]` | ❌ | Нельзя |
| Хранить указатели: `map[string]*T` | ✅ | Нужно менять объект по месту |
| Взять копию, поменять, вернуть обратно | ✅ | Работаешь со значением |

**Вариант A — храни указатели:**
```go
type Counter struct{ Count int }

m := map[string]*Counter{
    "apple": {Count: 3},
}
m["apple"].Count++   // ✅ работает
```

**Вариант B — работай с копией:**
```go
m := map[string]Counter{
    "apple": {Count: 3},
}
c := m["apple"]
c.Count++
m["apple"] = c       // записали обратно
```

**Что выбрать:**
- Часто мутируешь → `map[string]*T`.
- Просто хранишь → `map[string]T` (безопаснее).

> ⚠️ Указатели в map в конкурентном коде требуют дисциплины — но об этом в модуле про горутины.

---

## 3. Ссылочные типы не надо передавать по указателю

**Частый вопрос:** `slice`, `map`, `chan` — ссылочные. Может, передавать их как `*[]T`, `*map[K]V`, `*chan T`?

**Ответ:** не надо.

### Почему они «ссылочные»

**Слайс** — структура из 3 полей (под капотом):
```
[ptr → массив] [len] [cap]
```
Передаётся **по значению**, но копируется только эта «обёртка» (3 машинных слова) — **массив не копируется**. Поэтому изменения элементов видны снаружи:
```go
func change(s []int) { s[0] = 99 }
```

**Map** — под капотом просто указатель на `hmap`:
```
type map[K]V = *hmap
```
Передача map в функцию — это передача указателя. Изменения содержимого видны снаружи:
```go
func modify(m map[string]int) { m["hello"] = 42 }
```

**Chan** — так же, ссылка на внутреннюю структуру.

### Почему не `*[]T` / `*map[K]V`

1. **Нет выигрыша.** Обёртка и так маленькая (2–3 слова), передаётся дёшево.
2. **Лишний уровень косвенности.** Придётся писать `(*s)[0] = 99`, `(*m)[key] = v` — громоздко.
3. **Против идиом Go.** В стандартной библиотеке (`bytes.Buffer`, `sort.Slice`, `sync.Map`) ты не увидишь `*[]T` и `*map[K]V`.
4. **Нужно вернуть новый — верни его явно.** Хочешь изменить длину слайса — возвращай новый слайс, а не передавай `*[]T`.

> ✅ **Правило:** `[]T`, `map[K]V`, `chan T` передавай **как есть**, без `*`. Это уже «по ссылке».

### ⚠️ Единственный нюанс

Если внутри функции **переназначить** саму переменную map/slice/chan — изменения не выйдут наружу:
```go
func reassign(m map[string]int) {
    m = make(map[string]int)   // ⚠️ меняем локальную копию
    m["x"] = 1                 // снаружи ничего не изменится
}
```
Вот **для этого** может понадобиться `*map[K]V`. Но это редкий сценарий, и обычно его решают иначе — например, **возвращают новую map из функции**:
```go
func build() map[string]int { return map[string]int{"x": 1} }
```

## Запомнить

- **`&u` в `range`** — опасно до Go 1.22 (уникальный адрес только с 1.22). Пиши `&users[i]`.
- **`&m[key]`** — нельзя, значения map не имеют стабильного адреса.
- Нужно мутировать значение в map → храни `map[K]*T` или работай через копию.
- **`*[]T`, `*map[K]V`, `*chan T`** — не идиоматично, не нужно, усложняет код.
- Хочешь вернуть новый slice/map — **возвращай из функции**, не передавай указатель.
