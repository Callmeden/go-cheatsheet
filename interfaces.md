# Интерфейсы (Interfaces)

**Главное:** интерфейс — это набор **методов** (поведение), а не реализация. Тип удовлетворяет интерфейсу **неявно**: если реализовал все методы — ты уже реализация. Никакого `implements` писать не нужно. Это **duck typing**: «если выглядит как утка и крякает как утка — это утка».

## Объявление и неявная реализация

```go
type Speaker interface {
    Speak() string
}

type Human struct{ Name string }

func (h Human) Speak() string {
    return "Hello, my name is " + h.Name
}

var s Speaker = Human{Name: "Alice"}   // ✅ Human реализует Speaker
fmt.Println(s.Speak())
```

**Ключевое:**
- Реализация — автоматическая, если сигнатуры методов совпадают.
- Интерфейс может быть объявлен **в другом пакете** — тип всё равно его реализует.

## Явная проверка реализации (compile-time)

Гарантирует на этапе **компиляции**, что тип реализует интерфейс. Полезно, когда интерфейс в другом пакете.

```go
var _ Speaker = (*Human)(nil)
```

| Часть | Смысл |
|---|---|
| `var _ Speaker` | переменная типа `Speaker`, `_` = «не использовать» |
| `(*Human)(nil)` | nil-указатель на `Human` |
| Вся строка | если `*Human` **не** реализует `Speaker` → **ошибка компиляции** |

**Зачем:** защита от регрессий. Удалил метод — код не соберётся, узнаешь сразу.

⚠️ **Нюанс:** если метод на **pointer receiver** — нужен `(*Human)`. Если на value receiver — можно `Human` или `(*Human)`.

**Альтернатива:** комментарий `// Human implements Speaker` — это документация, компилятор её **не проверяет**.

## Пустой интерфейс

`interface{}` (синоним `any` с Go 1.18) — интерфейс **без методов**. Ему удовлетворяет **любой тип**.

```go
func PrintValue(v interface{}) {
    fmt.Println(v)
}

PrintValue(42)
PrintValue("Hello")
PrintValue([]int{1, 2})
```

**Когда:** тип значения неизвестен заранее (логирование, JSON, обобщённые контейнеры).

⚠️ **Избыточное использование** → теряешь типизацию и читаемость. Если знаешь типы — бери конкретный интерфейс или дженерики.

## Type assertion (приведение типа)

```go
if value, ok := v.(int); ok {
    fmt.Println("Integer value:", value)
} else {
    fmt.Println("Unknown type")
}
```

| Форма | Поведение |
|---|---|
| `v.(T)` | **паника**, если `v` не типа `T` |
| `v, ok := v.(T)` | **безопасно**: `ok = false`, если не совпал |

**Правило:** в проде — **всегда с `ok`**. Без `ok` — только если абсолютно уверен в типе.

## Type switch

```go
switch v := v.(type) {
case int:
    fmt.Println("Integer:", v)   // v — int
case string:
    fmt.Println("String:", v)    // v — string
default:
    fmt.Println("Unknown type")
}
```

- Внутри `case` переменная `v` **уже нужного типа**.
- `default` — обязателен, если не уверен в покрытии.

## Нулевые интерфейсы — главная ловушка

**Правило:** интерфейс считается `nil` **только если и тип, и значение внутри — nil**.

```go
var i interface{} = nil
fmt.Println(i == nil)    // true

var p *int = nil
var j interface{} = p
fmt.Println(j == nil)    // false ❗
```

**Устройство интерфейса под капотом** — это пара `(тип, значение)`:

| Ситуация | Тип | Значение | `== nil`? |
|---|---|---|---|
| `var i interface{} = nil` | nil | nil | ✅ true |
| `var j interface{} = (*int)(nil)` | `*int` | nil | ❌ false |

Во втором случае **тип задан** (`*int`), поэтому интерфейс **не пустой**, хотя значение внутри nil.

**Как проверить, что внутри nil-указатель:**

```go
if ptr, ok := j.(*int); ok && ptr == nil {
    fmt.Println("внутри nil указатель")
}

// или через reflect
if reflect.ValueOf(j).IsNil() {
    fmt.Println("внутри nil")
}
```

⚠️ **Где стреляет:** функция возвращает `error`, но внутри — nil-указатель на структуру. Переменная `error != nil`, хотя «по логике» ошибки нет. Ты **пропускаешь ошибку**, думая, что её нет.

## Duck typing

Совместимость — по **набору методов**, а не по имени типа.

```go
type Walker interface{ Walk() string }

type Dog struct{}
func (d Dog) Walk() string { return "The dog is walking" }

type Robot struct{}
func (r Robot) Walk() string { return "The robot is walking" }

func MakeWalk(w Walker) { fmt.Println(w.Walk()) }

MakeWalk(Dog{})
MakeWalk(Robot{})
```

## Композиция интерфейсов

Интерфейсы **встраивают** друг друга — получается составной интерфейс.

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}

type Writer interface {
    Write(p []byte) (n int, err error)
}

type ReadWriter interface {
    Reader
    Writer
}
```

Любой тип, реализующий **оба** метода, автоматически удовлетворяет `ReadWriter`.

## Встраивание структур

Работает и для **структур**: встроенный тип «отдаёт» свои методы.

```go
type Logger struct{}
func (l Logger) Log(msg string) { fmt.Println(msg) }

type Service struct {
    Logger   // встроенное поле
}

s := Service{}
s.Log("Hello, world!")   // метод Logger доступен через Service
```

## Лучшие практики

| № | Практика | Почему |
|---|---|---|
| 1 | Интерфейсы — **маленькие** (1–2 метода) | Проще комбинировать, легче реализовать |
| 2 | Использовать интерфейсы **для абстракции**, а не везде | Не плодить лишние уровни |
| 3 | Избегать `interface{}`, если известны типы | Теряется типизация, растут проверки |
| 4 | Использовать **стандартные** (`io.Reader`, `io.Writer`, `error`) | Единый стиль, совместимость |
| 5 | Не бояться возвращать конкретные типы | Абстракция нужна не всегда |
| 6 | Интерфейсы — для **моков в тестах** | Позволяет подменять реальные зависимости |

## Подводные камни

### 1. `interface{}` != `nil`, если внутри nil-указатель
Классическая ошибка в обработке ошибок. Интерфейс смотрит на **пару (тип, значение)**, а не только на значение.

### 2. Type assertion без `ok` → паника
В проде — только `v, ok := i.(T)`.

### 3. `interface{}` вместо конкретного типа → теряешь проверки компилятора
Растут `switch` и `ok`-проверки, код становится хрупким.

### 4. Интерфейс с большим количеством методов — плохой дизайн
Дроби на маленькие (как `io.Reader` / `io.Writer`).

### 5. `var _ I = (*T)(nil)` — про pointer vs value receiver
Если метод на **pointer receiver** — обязательно `(*T)`. Иначе компилятор скажет, что `T` не реализует `I`.

## Запомнить

- **Интерфейс = набор методов.** Реализация — **неявная**.
- `var _ Speaker = (*Human)(nil)` — **compile-time проверка** реализации.
- **`interface{}` / `any`** — пустой интерфейс, принимает любой тип.
- **Type assertion:** `v, ok := i.(T)` — с `ok`. Без `ok` — паника.
- **Type switch:** `switch v := i.(type)` — переменная внутри `case` уже нужного типа.
- **Интерфейс под капотом — пара `(тип, значение)`.**
- **`nil`-интерфейс ≠ интерфейс с `nil`-значением.** Проверка `i == nil` требует, чтобы **и тип, и значение** были nil.
- **Композиция интерфейсов** — через встраивание (`Reader`, `Writer` → `ReadWriter`).
- **Встраивание структур** — «отдаёт» методы встроенного типа.
- **Интерфейсы — маленькие.** Один-два метода.
- **`interface{}` — только когда тип реально неизвестен.** Иначе — конкретный интерфейс.
