# Задание 4: Обобщённое двоичное дерево поиска (BST)

## Условие

Реализовать обобщённое BST, которое поддерживает:

| Операция | Команда | Что делает |
|---|---|---|
| Вставка | `Insert <key> <value>` | Вставить элемент |
| Поиск | `Find <key>` | Найти по ключу |
| Удаление | `Delete <key>` | Удалить по ключу |
| Обход | `InOrder` | Вывести значения по возрастанию ключей |

**Ключи:** любые `cmp.Ordered` (в тестах — `int`).
**Значения:** `any`.
**Ввод/вывод:** STDIN → STDOUT.

### Формат вывода
- `Insert` — ничего.
- `Find` — `<value>` или `not found`.
- `Delete` — ничего.
- `InOrder` — значения через пробел.

### Пример
```
Insert 10 A
Insert 5 B
Insert 15 C
Find 10
Delete 5
InOrder
Find 5
```
Вывод:
```
A
A C
not found
```

## Что изучил

- **Дженерики:** `Tree[K cmp.Ordered]`, `Node[K cmp.Ordered]`.
- **Рекурсивные структуры** через указатели (`*Node[K]`).
- **BST:** вставка, поиск, in-order обход.
- **Удаление из BST — три случая:**
  1. Лист → обнулить ссылку у родителя.
  2. Один ребёнок → заменить ссылку у родителя на ребёнка.
  3. Два ребёнка → найти минимум в правом поддереве, скопировать `Key`/`Value`, удалить минимум.
- **Тонкость:** `parentOfTargetNode` может оказаться **самим удаляемым узлом** — если у `child.Right` нет левого ребёнка. Отслеживал булевой переменной «был ли заход в цикл».
- **`InOrder`** — левый → корень → правый.
- **`cmp.Ordered`** из стандартной библиотеки (не `x/exp/constraints`).
- **Дженерики:** `Tree[int]` и `Tree[string]` — **разные типы**, экземпляры создаются под **конкретный** тип.
