# ООП в Go: принципы и реализация

**Главное:** Go — **не классический ООП-язык**. В нём нет классов, наследования `extends` и перегрузки методов. Но **все четыре принципа ООП** (инкапсуляция, абстракция, полиморфизм, наследование) в нём **реализованы** — просто через другие механизмы: структуры, методы, интерфейсы и **композицию/встраивание**.

## Четыре принципа ООП — кратко

| Принцип | Суть | Одной фразой |
|---|---|---|
| **Инкапсуляция** | Скрыть внутреннее устройство, открыть только нужный интерфейс | «Не лезь под капот» |
| **Абстракция** | Говорить о сути, а не о деталях реализации | «Говори про суть, а не про детали» |
| **Полиморфизм** | Один вызов — разное поведение у разных типов | «Одна команда — разные действия» |
| **Наследование** | Переиспользовать поведение существующего типа | «Добавь к уже готовому» |

## 1. Инкапсуляция

В Go реализуется через **регистр первой буквы**:

- **Заглавная** → экспортируется (доступно из других пакетов).
- **строчная** → приватное (только внутри пакета).

```go
package user

type User struct {
    name  string   // неэкспортируемое — снаружи не видно
    Email string   // экспортируемое — доступно из других пакетов
}

// Экспортируемые методы — публичный интерфейс
func (u *User) SetName(name string) { u.name = name }
func (u *User) GetName() string     { return u.name }

// Неэкспортируемый метод — только внутри пакета
func (u *User) isEmpty() bool {
    return u == nil || (u.name == "" && u.Email == "")
}
```

```go
package main

import (
    "fmt"
    "myproject/user"
)

func main() {
    u := &user.User{Email: "user@example.com"}
    u.SetName("Alice")

    // u.name = "Bob"   // ❌ ошибка компиляции
    // u.isEmpty()      // ❌ ошибка компиляции

    fmt.Println(u.GetName())   // Alice
    fmt.Println(u.Email)       // user@example.com
}
```

**Суть:** внутреннее состояние (`name`) контролируется через публичный интерфейс (`SetName` / `GetName`).

## 2. Абстракция

В Go выражается через **интерфейсы**. Интерфейс описывает **что умеет объект**, не уточняя **как**.

```go
type Speaker interface {
    Speak()
}

type Dog struct{}
func (d Dog) Speak() { fmt.Println("Гав") }

type Cat struct{}
func (c Cat) Speak() { fmt.Println("Мяу") }

func MakeSound(s Speaker) {
    s.Speak()
}
```

Функция работает **не с собакой или кошкой**, а с **абстракцией** — «кто угодно, кто умеет `Speak`».

## 3. Полиморфизм

Строится **на интерфейсах**. Один и тот же код вызывает один и тот же метод, но поведение зависит от конкретного типа.

```go
dog := Dog{}
cat := Cat{}

MakeSound(dog)   // Гав
MakeSound(cat)   // Мяу
```

Снаружи вызов одинаковый. Реализация — своя у каждого.

## 4. Наследование (которого нет)

**В Go нет наследования** в классическом виде. Нельзя написать `type Dog extends Animal`.

Вместо этого — **композиция** и **встраивание (embedding)**.

### Встраивание (embedding)

```go
type Animal struct {
    Name string
}

func (a Animal) Eat() {
    fmt.Println(a.Name, "ест")
}

type Dog struct {
    Animal   // встроенный тип — Dog «получает» поля и методы Animal
}

d := Dog{Animal: Animal{Name: "Шарик"}}
d.Eat()   // Шарик ест
```

### Переопределение метода

```go
func (d Dog) Eat() {
    fmt.Println("Собака по кличке", d.Name, "ест")
}

d.Eat()   // Собака по кличке Шарик ест
```

### Расширение метода (вызов родительского через embedding)

```go
func (d Dog) Eat() {
    d.Animal.Eat()              // явно вызываем метод Animal
    fmt.Println(d.Name, "- собака")
}

d.Eat()
// Шарик ест
// Шарик - собака
```

⚠️ **Важно:** снаружи похоже на наследование, но **это не оно**. `Dog` **не является** «подклассом» `Animal`. Он **содержит** `Animal` внутри. Философия Go: **композиция важнее наследования**.

## Как принципы ООП ложатся на Go

| Принцип | Механизм в Go |
|---|---|
| Инкапсуляция | Регистр первой буквы (экспорт/неэкспорт) |
| Абстракция | Интерфейсы |
| Полиморфизм | Интерфейсы |
| Наследование | Композиция + встраивание (embedding) |

## Подводные камни

### 1. «Наследование» в Go — это не наследование
`Dog` не является подтипом `Animal`. Это **композиция**. Не путай с классическим ООП.

### 2. Нет перегрузки методов
Нельзя объявить два метода с одним именем и разными параметрами. Одна сигнатура — один метод.

### 3. Экспорт работает на уровне **пакета**, а не типа
Приватное поле `name` недоступно **нигде** за пределами пакета — даже в другом файле того же модуля, но **другого пакета**.

### 4. Встраивание — не всегда хорошо
Если встроить два типа с одинаковым методом — **неоднозначность**. Компилятор попросит уточнить: `d.TypeA.Method()` или `d.TypeB.Method()`.

### 5. Метод на встроенном типе — не переопределение
`Dog.Eat()` **не переопределяет** `Animal.Eat()`. Оно **перекрывает** (shadowing) — если вызвать через `Animal` явно, вызовется версия `Animal`.

## Запомнить

- Go — **не классический ООП-язык**: нет классов, `extends`, перегрузки.
- **Инкапсуляция** = регистр буквы (Заглавная = экспорт, строчная = приват).
- **Абстракция** = интерфейсы.
- **Полиморфизм** = интерфейсы (один вызов — разное поведение).
- **Наследования нет.** Вместо него — **композиция** и **встраивание (embedding)**.
- Встраивание: `Dog` содержит `Animal` → получает его поля и методы.
- «Переопределение» через embedding — это **shadowing**, не override.
- Философия Go: **композиция важнее наследования**.
- Простые решения > избыточные абстракции.
